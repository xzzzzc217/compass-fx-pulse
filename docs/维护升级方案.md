> CompassFXPulse 已有的"业务场景（外汇风险）+ 数据（爬虫+API）+ 模型（LoRA + TimeXer）+ 端到端工程（Vue+Flask+MySQL）"是**绝佳土壤**，只需要把"传统 Web + 单轮 LLM"升级成"多 Agent + RAG + Tool 编排"，每一处都精准击中 JD 的能力要求和加分项。

### Phase 2 · 第 1 周 — Function Calling Agent（JD 必备）

**改造点**：把"用户输入 → 直接喂 LLM"改成"用户输入 → 意图识别 → 调用工具 → LLM 总结"。

```python
# backend/app/agent/tools.py
from langchain_core.tools import tool

@tool
def get_exchange_rate(currency_a: str, currency_b: str, date: str) -> dict:
    """查询指定日期的汇率，date 格式 YYYY-MM-DD"""
    ...

@tool
def predict_exchange_rate(currency_a: str, currency_b: str, horizon_days: int) -> dict:
    """调用 TimeXer 预测未来 horizon_days 天的汇率"""
    ...

@tool
def search_forex_news(query: str, k: int = 5) -> list:
    """从新闻库检索相关外汇新闻"""
    ...

@tool
def calculate_forex_risk(currency: str, exposure_amount: float, horizon_days: int) -> dict:
    """根据敞口和波动率计算 VaR"""
    ...
```

**面试讲法**：
> "我把原来的单轮 LLM 调用重构成 Function Calling Agent，定义了 4 个工具：行情查询、预测、新闻检索、风险计算。LLM 自己决定调用哪个，而不是把所有上下文一次性塞进 prompt。这样做有三个好处：① 把 LLM 不擅长的精确数值计算外包给确定性逻辑（JD 原话"通过 LLM 或确定性逻辑兜底实现"）；② 每个工具可独立测试和迭代；③ Token 消耗降低 60% 以上。"

### Phase 2 · 第 2 周 — RAG 知识库（JD 必备）

**素材**（你已有的）：
- 爬虫已抓的"外汇.csv / 美联储.csv / 澳大利亚.csv / 彭博社历史.csv"等新闻
- 央行政策 PDF（去美联储 / ECB / BOJ / 人民银行官网下载季度报告）
- 你自己写的"花旗杯技术文档.pdf"

**实现**（推荐 LlamaIndex 而非 LangChain，对中文 + 表格友好）：
```python
# backend/app/rag/pipeline.py
from llama_index.core import VectorStoreIndex, SimpleDirectoryReader
from llama_index.embeddings.huggingface import HuggingFaceEmbedding
from llama_index.vector_stores.qdrant import QdrantVectorStore
from llama_index.postprocessor.flag_embedding_reranker import FlagEmbeddingReranker

embed_model = HuggingFaceEmbedding(model_name="BAAI/bge-m3")
reranker = FlagEmbeddingReranker(model="BAAI/bge-reranker-v2-m3", top_n=5)

# 切块策略：政策文档用 SemanticSplitter，新闻用 SentenceSplitter
# 检索：dense（bge-m3）+ sparse（BM25）混合，再 rerank
```

**关键设计**（面试加分）：
1. **元数据过滤**：每个 chunk 带 `{currency, date, source}`，问"日元最近的政策"时，先 metadata 过滤，再向量召回
2. **召回质量监控**：埋点记录 query → 召回 top-k → 用户是否点了"有帮助"，定期分析 recall@k
3. **上下文注入策略**：检索结果按"权威度"加权（央行原文 > 路透 > 自媒体）
4. **拒答机制**：rerank 分数 < 阈值时，直接回"我没有足够依据"，避免幻觉（JD 要求"幻觉的工程化应对"）

### Phase 3 · 第 4 周 — 多 Agent 编排（JD 核心要求）

升级到 **LangGraph** 状态机，做"多 Agent 协作"：

```
用户问："欧元/美元下个月怎么走？"
       │
       ▼
  ┌────────────┐
  │ Router     │ ── 判定为"预测+解读"复合问题
  └────┬───────┘
       ├──→ 数据 Agent：拉历史汇率 + 近 30 天新闻
       ├──→ 预测 Agent：调 TimeXer，输出预测区间 + 置信度
       ├──→ 政策 Agent：RAG 检索最近 ECB / Fed 决议
       └──→ 风险 Agent：根据用户敞口算 VaR
              │
              ▼
       ┌────────────┐
       │ Synthesizer│ ── LLM 综合四个 Agent 输出，生成报告
       └────┬───────┘
            ▼
       ┌────────────┐
       │ Reflector  │ ── 自检：数字是否一致？引用是否完整？
       └────┬───────┘
            ▼
         返回前端
```

**面试讲法**：
> "我用 LangGraph 把外汇分析拆成 5 个 Agent，每个 Agent 单一职责。Synthesizer 负责融合，Reflector 做反思纠错——如果检测到预测区间和历史波动率不一致，会回到 Predict Agent 重新调用。这套架构对应 JD 里的"意图识别、任务拆解、反思纠错闭环"。"

### Phase 4 · 第 5 周 — 评测 + 观测（JD 第 5 条）

**评测集**（手工 + LLM 合成混合，约 100 题）：
- 事实查询类：30 题（如"2025-12-15 USD/JPY 收盘？"）→ 精确匹配评分
- 预测推理类：30 题 → LLM-as-Judge 评分（参考维度：合理性 / 引用充分度 / 不确定性表达）
- 政策解读类：20 题 → 人工评分 + LLM 评分对比
- 抗幻觉类：20 题（故意问无依据的问题）→ 看是否拒答

**观测**：
- 接 [Langfuse](https://langfuse.com)（开源，本机 docker 起）做全链路 Trace
- 每次 Agent 调用记录：用户 query → 路由决策 → 工具调用顺序 → token 消耗 → 延迟 → 用户反馈
- 在 README 放一张"7 天调用瀑布图"

### Phase 5 · 第 6 周 — 性能 & 安全（JD 第 6 条）

**性能**：
- 后端 Flask → FastAPI（async + SSE 原生支持）
- 高频 query（如"USD/JPY 今天汇率"）走 Redis 缓存，TTL 60s
- LoRA 推理走 vLLM（JD 加分项写明"vLLM、KV cache 优化"）
- 流式输出已有，加 SSE 心跳防超时

**安全**：
- Prompt 注入检测：对用户输入跑一道分类器，检测"忽略上面所有指令"等模式
- 工具调用沙箱：calculate_forex_risk 等工具用 RestrictedPython 执行
- 输出 PII 过滤：正则 + LLM 二次审查
- RAG 引用校验：所有"事实型回答"必须返回 source URL，没引用就拒答
